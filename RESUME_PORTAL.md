# Resume + Apply Portal

The job scraper can route each new job through a browser-only resume tailoring page before opening the company's real application.

## What happens when you click Apply

1. GitHub/Telegram opens `https://harsha271199.github.io/job-scraper/?job=<id>`.
2. The portal loads public job signals generated by the scraper: company, title, location, role profile, detected skills, and the real application URL.
3. On the first use on a browser, import your private `master_resume.json`.
4. The master is saved in that browser's local storage. It is not committed to this public repository.
5. The page chooses up to 15 JD-matching skills that are present in your private master and selects only bullets with `verified: true`.
6. Click **Download DOCX + Open Application**.
7. A clean one-column `.docx` is generated in the browser and the official company application opens in a new tab.

## First-time setup

Use the reconciled private master resume file and keep it outside Git. A recommended local layout is:

```text
job-scraper/
  resume_private/
    master_resume.json
```

The `resume_private/` folder is already ignored by Git.

When the portal first opens, choose `master_resume.json`. After that, the same browser remembers it. Use **Clear private resume** on the portal to remove the local copy.

## Privacy model

The public repository contains:

- portal code;
- a skill inventory;
- derived job signals;
- the real public job application URLs.

It does **not** contain the private master resume, email, phone number, or generated application resumes. The browser reads the master locally and generates the DOCX locally. No generative-AI API is called by the portal.

## Job-description handling

For each newly discovered job, `resume_portal_feed.py` attempts to read the public job page and extracts only derived skill/profile signals. The full job description is not copied into `job_signals.json`.

Workday links receive an additional attempt through Workday's public CXS job-detail endpoint. If a site blocks readable job text, the portal falls back to title/profile signals and clearly says so.

## Truth-preserving rules

- `verified: false` bullets are never selected.
- Locked employer, title, dates, education, and project facts are not rewritten.
- The portal does not invent missing JD skills.
- Only skills already in the private master's `base_skills` can be rendered.
- No hidden white text, comments, watermark objects, or generated graphics are added by the portal.

## GitHub Pages

The portal is deployed by `.github/workflows/pages.yml` from the `portal/` directory. The build bundles the pinned `docx` JavaScript library into the site so the live page does not need to load resume-generation code from a third-party CDN.

If GitHub Pages has never been enabled for the repository, enable it once under **Settings → Pages → Build and deployment → Source: GitHub Actions**. After that, the deployment workflow maintains the site automatically.
